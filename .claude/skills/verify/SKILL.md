# Verifying DitoDitoInfinito at runtime

## Launch

- Dev server with rebuild-on-change: `trunk serve --port 8099` (run in the background). It auto-reloads the page on every rebuild, so **do not** use it for long runs while editing.
- Stable static build for long tests: `trunk build --release --public-url / --dist dist-test` then `cd dist-test && python3 -m http.server 8098 --bind 127.0.0.1`.
- `just check` covers native crates, the wasm app, SEO regen and REUSE lint. `just test` runs native tests (chart, engine, xtask).

## Routes (hash router, works under any public URL)

- `#/` song list (fetches `songs/index.json`, generated by `cargo run -p xtask -- gen-songs` as a Trunk pre-build hook).
- `#/play?song=<id>&chart=<n>` gameplay; `&auto=1` plays the chart automatically (scripted presses at each note's judged time), `&gfx=gl` forces the WebGL2 backend. Song ids are the directory names under `assets/songs/`. The chart index is the position in `Song::charts` (see the manifest's `charts[].index`).
- `#/calibrate/run?mode=visual|audio|combined` converging calibration on the gameplay path; `&auto=1&bias=<ms>` autoplays with a deliberate late (+) or early (−) bias so convergence can be checked (expect the result card to show `+<bias> ms` and "Converged"). `&bias` also works on `#/play`.
- `#/options`, `#/calibrate`, `#/credits` (reads `credits/credits.json` from `xtask gen-credits`).

Gameplay waits for a user gesture ("press Enter or click to start"); Esc aborts back to the list. In a fresh profile a manual (non-autoplay) start first shows the new-device prompt: click "play with defaults". The song list shows one style (layout) at a time: `.style-button` picks Single / Solo / Double (only styles the library has charts for; the bundled songs have Single and Double, solo needs an imported `dance-solo` chart). Charts on the Dancing☆Onigiri key modes the game plays (5, 7, 7i, 9A, 9B) can be written as `.sm` files with a `danoni-<mode>` steps type (`danoni-7i`, rows as wide as the mode) and imported like any pack; other modes are left out on import. A chart that fails (ITG fails on misses) ends the session and freezes `__DDI_DEBUG`, so manual input tests need charts whose notes start late. Settings live in `localStorage` under `ddi.settings.v1`.

## Engine debug state

While a session runs, `window.__DDI_DEBUG` is refreshed every 20 frames: `{frames, backend, srgb_view, song_time, combo, max_combo, taps:[W1..Miss], held, let_go, finished, failed, drift, output_latency, audio, pressed:[per lane], pads, pad_polls, pad_fast}` (`held` counts held notes; `pressed` is which lanes are down right now; `srgb_view` is whether the scene is drawn through an sRGB view, expected `true` on both backends). `audio` (also a line in the debug overlay) reads e.g. `audio: Running · 48000 Hz · master 1.00 · output peak -20.1 dBFS · volume 0.80`: the output peak comes from an analyser on the master output, so it tells "the game outputs nothing" from "the output goes nowhere". Read it with `page.evaluate(() => window.__DDI_DEBUG)`.

`window.__DDI_FORCE_WASM_DECODE = true` (set before starting a session, e.g. with `page.addInitScript`) skips `decodeAudioData` and decodes the song with the built-in Symphonia decoder, the fallback Safari needs for Ogg Vorbis. It only handles Ogg Vorbis: on the bundled songs (Ogg Opus) the session must stop on an error naming both decoders ("Built-in decoder: Ogg Opus is not supported"), not crash. To exercise it end to end, transcode a bundled song to Vorbis in a scratch dist only (`ffmpeg -i x.opus -c:a libvorbis x.ogg` if your ffmpeg has libvorbis, else `sndfile-convert -vorbis` from libsndfile; keep the original file name so the manifest still points at it) and check the console for "decoded in wasm instead". The same fallback runs when the browser's decode comes back silent (Safari with Ogg Vorbis); it logs "decodeAudioData returned silence; decoded in wasm instead". Previews play through Web Audio: test them with `--autoplay-policy=document-user-activation-required` so only a real click can start them.

## Imported songs

The song list's import panel has two pickers. Where `showDirectoryPicker` exists (Chrome, headless too) "choose folder" is a button that keeps the folder's handle for re-reading; elsewhere it is a hidden `webkitdirectory` input. For the input in Chrome, `page.addInitScript(() => { delete window.showDirectoryPicker; })`: then `.import-panel input[type=file]` index 0 is the folder picker and index 1 takes zips or loose files (without it, only the zip/files input is there). To test the handle path, make the picker return an OPFS folder the test filled (`window.showDirectoryPicker = async () => (await navigator.storage.getDirectory()).getDirectoryHandle('Packs')`; OPFS handles are granted and can be kept in IndexedDB): an open pack imported from it then offers "re-read folder", which imports the folder again and removes the songs from that folder whose folders are gone. Such imports are linked (records carry `links`; the `files` store holds only charts and banners) unless "store a chosen folder's songs in the browser" is ticked. OPFS handles are always granted; to see the play page's "allow reading the folder" prompt, override `FileSystemHandle.prototype.queryPermission` to answer `prompt` (and `requestPermission` to grant) in an init script. Playwright's `setInputFiles` accepts a directory path for the first and a `.zip` for the second; wait until `.import-status` no longer says "importing"/"reading". Imports land in IndexedDB (`ddi-library`, stores `songs` and `files`), so use a fresh browser context for a clean library. Build test packs in a scratch dir (a pack folder of song folders; copy a bundled song, rename files to test case-insensitive lookups, write a short `.sm` by hand to cover rolls, mines, lifts and fakes, and zip it with `zip -r` and `zip -r0` for deflated and stored entries). An autoplayed chart must end with only top-tier judgements, `let_go` 0 and no mines hit.

## Headless Chrome

No playwright in the repo. In a scratch dir: `npm i playwright-core`, then launch the installed Chrome:

```js
const { chromium } = require('playwright-core');
const browser = await chromium.launch({ channel: 'chrome', headless: true,
  args: ['--enable-unsafe-webgpu', '--use-angle=metal', '--autoplay-policy=no-user-gesture-required'] });
```

WebGPU works headless with those flags (the badge in the bottom-right corner shows the backend). Chrome flags do not reliably disable WebGPU; use `&gfx=gl` to exercise the fallback instead. Click `.start-prompt` to start a session; wait; then screenshot and read `__DDI_DEBUG`. A full autoplay of the shortest chart (Sweeteners Beginner, ~2:40) ends on the results overlay (`.results-card`).

## Gamepads without hardware

`fake-gamepad.js` (next to this file) replaces `navigator.getGamepads` with scripted pads: `page.addInitScript({ path })`, then `window.__DDI_FAKE_PAD.add({ id, mapping: '' | 'standard', buttons, axes, hatAxis, trustTimestamp })`, `.press(i, control)`, `.release(i, control)`, `.disconnect(i)`, with controls as stored in bindings (`button:3`, `axis:1-`, `hat:9:left`). Add the pad in an init script (before the app loads) or later; the app finds pads by polling. Bindings for a non-standard pad can be seeded in `localStorage` (`ddi.settings.v1`, `pads: [{ id, single: [[…], …], layouts: { "dance-solo": [[…], …] }, start, back }]`; keyboard tables per layout under `keys`); a standard pad gets the d-pad/face-button defaults for each built-in layout. Two fake pads with the same id play one half of `dance-double` each (lower index on the left) with their single bindings; `__DDI_DEBUG.pressed` shows which of the eight lanes are down.

`#/play?…&auto=pad` autoplays through pad 0: the autoplayer schedules each press on the fake pad ahead of time (`schedule(hostMs, control, pressed)`), the fake applies it when `getGamepads()` is called at or after that time, and the edge reaches the engine through the real poller. With `trustTimestamp: true` the pad's `timestamp` is the exact edge time and the mean error should be ~0 ms; with `false` the app stamps the poll time and the mean should be about +0.5 ms (1 ms loop), σ well under 1 ms. `__DDI_DEBUG.pads` shows how each pad's edges were stamped, `pad_polls` the polls per second (~900 with the 1 ms loop) and `pad_fast` whether the loop runs. A fresh profile shows the new-device prompt; Start (button 9 on a standard pad) continues past it. Gamepad presses count as a user gesture in Chrome and Firefox only for real pads, so the headless autoplay flag is what lets the audio start here.

## Touch lanes

Use a context with `hasTouch: true, isMobile: true` and a phone viewport (390×844 and 844×390), tap `.start-prompt`, and send touches with CDP `Input.dispatchTouchEvent` (several `touchPoints` for jumps, `touchMove` to slide between columns). Columns split at the midpoints between receptors, the outer ones run to the screen edges; only touch and pen press lanes (mouse never does). On touch devices a ✕ button replaces the back link during play and runs the cancel gesture (hold or double tap). Check `__DDI_DEBUG.pressed` and that the page neither scrolls nor zooms.

## Dancing☆Onigiri works

Import a folder holding a work's pages (`.html` with an inline `id="dos"` input, or an `externalDos` file next to it) and its `music/` folder, or a dump folder of the research tool (`manifest.json`; the local corpus is `~/Music/DanOni/corpus`, third-party, local only). danoniplus's own sample pages (`danoni/` of its repository, MIT) make a quick site: copy them with a `music/nosound.mp3` (any audio renamed) and import the folder. Charts appear under their key mode in the style selector ("5 keys", "7 keys", "7i keys", "9A keys", "9B keys"); works in other modes are listed as left out. Onigiri, giko and iyo lanes draw as a star, a square and a circle. Autoplay must stay all top tier. `DDI_DANONI_CORPUS=<dir> cargo test -p ddi-chart --test danoni_corpus -- --nocapture` compares the importer with danoniplus's parse of every captured chart.

Options that only matter for works, set in `ddi.settings.v1` before opening a play page: `ruleset_mode` (`"AllStepMania"` default, `"Original"`, `"AllDanoni"`), `danoni` (`{gauge, range, excessive}`), `speed_source` (`"Player"`/`"Chart"`), `chart_colors` (bool), `lyrics` (bool, default on). Under a work's own rules an autoplay ends AP with 1,000,000 and fast/slow 0/0; the results card shows the work's tier names. Lyrics are `.lyric.top`/`.lyric.bottom` elements in `.lyrics` (text, `opacity`, `font-size`); no corpus work's captured music has lyrics, so add a `|word_data=…|` field (`frame,depth,text`, `frame,depth,[fadein],frames`) to a copy of a test work in a scratch folder. Such a copy with `musicNo=0$1`, two music files and `startFrame`/`endFrame`/`fadeFrame` lists checks the rest: both songs reference one `works/<hash>` key in the `files` store (read IndexedDB `ddi-library` from the page), removing one song keeps it and removing both drops it, the second song starts at its `startFrame` (`song_time` ≈ (frame − 200)/60) and the `audio` debug line reads `master 0.00` after `endFrame` or the fade.

## Song list

Packs are an accordion (`.pack-header` buttons with `aria-expanded`; `data-pack-header` holds the key, `bundled` or `pack:<name lowercased>`); the open pack and the last chart started live in `sessionStorage` (`ddi.menu.v1`), so after the back link the same pack is open and that chart button is focused with the `nav-current` class. Arrow keys and Escape move through the list (`data-nav-row` rows, `data-nav-item` items); a standard fake pad moves with the d-pad (`button:12`–`15`) or the left stick, confirms with `button:0` or Start and goes back with `button:1` or Back; a held direction repeats after 350 ms. Pack banners come from images at the pack folder's root (StepMania's rule). Shift-JIS simfiles and zip names decode when the text reads as Japanese: build a zip whose names are raw Shift-JIS bytes without the UTF-8 flag (Python's `zipfile` needs `ZipInfo._encodeFilenameFlags` patched).

## Background changes

No bundled song has `#BGCHANGES`. For shared folders, import a folder holding a song and a `RandomMovies/` folder (or the two separately, in either order); the import report must say how many shared images were stored, and warns about images found nowhere (never about videos). Otherwise build a test pack in a scratch dir: copy a bundled song folder, add a few generated solid-colour images (one in a subfolder, one with different case), write a `#BGCHANGES` line with cuts, `CrossFade` (field 4 = 1) and named transitions in field 9, import it through the folder input, autoplay it, and sample a background pixel outside the field as `__DDI_DEBUG.song_time` passes each change (crossfades show the in-between colour).

## Video decoder

`just video` builds the FFmpeg module into `target/video/`; Trunk's post-build hook (`xtask stage-video`) copies it into the site's `video/` when it exists, and a build without it still runs (movies then fail with "the video decoder is not included in this build"). `just video-check` checks the module under Node on generated clips (`target/video/clips/`, FFmpeg's test pattern, safe to copy anywhere); `just video-check <file>` on one file. In the browser, `#/video-check` (not linked from the menus) decodes picked movies in the worker, then seeks and compares frames by fingerprint; `#/video-check?src=clips/a.avi,clips/b.avi` checks files of the site instead (copy the generated clips into the scratch dist). Results are in `window.__DDI_VIDEO_CHECK` (`{running, status, error, files: [{name, state, error, codec, width, height, frames, decode_ms_per_frame, wall_ms_per_frame, first_pts, last_pts, matrix, full_range, seeks, seeks_ok, seek_failures, slowest_seek_ms}]}`); wait until `running` is false. To test movie playback against the clock, make clips whose frames are solid colours coding their number (`-vf "geq=r='16*mod(N\,16)+8':g='16*mod(floor(N/16)\,16)+8':b='16*floor(N/256)+8'"` on a `color=black` source, `mpeg4 -bf 0 -q:v 1`; channel levels 16k+8 survive the codec), name them in a 120 BPM simfile's `#BGCHANGES` (beat b at b/2 s: a first run, an image, the movie again to resume, a rewinding short clip that loops, a rate of 2, a change at a negative beat to join mid-movie), import with `import_videos` on, `bg_brightness` 1 and `field_filter` 0, autoplay, and at chosen times read `window.__DDI_SONG_TIME` (the song time of each drawn frame) before and after a 1×1 `page.screenshot` left of the field; the decoded number must fall in the frames expected for that window, from `backgrounds::movie_position` and StepMania's 0.5 s loop restart. `__DDI_DEBUG.video` reports `{decoded, shown, dropped, late, seeks, open, playing, failed, module}`. To test importing movies, build a scratch pack: a bundled song's folder with a `#BGCHANGES` line naming generated clips (H.264 AVI, an MP4 written without `-movflags +faststart` so its index is at the end, an MPEG-2 `-f vob` program stream, an AV1 `libsvtav1` MKV for "cannot play", a name with no file) and a `RandomMovies/` folder with another clip. Import it copied (`import_videos` off and on in `ddi.settings.v1`), linked (an OPFS folder, as above) and as a deflated zip; the record's `entry.bg_videos` holds each movie's sniffed format and `stored`, the `files` store holds copied movies under `<id>/bg/…` and shared ones under `shared/…` (a JSON `SharedLink` when linked). `DDI_MOVIES=<dir> cargo test -p ddi-library local_movies -- --nocapture` sniffs a local folder's movies. Expect every seek exact and, on an Apple Silicon laptop, about 0.8 ms/frame for Xvid and MPEG-2 at 640×360 and 3–4 ms for H.264 at 480p–720p. Decoder messages appear in the console prefixed `[video]`.

Video settings and the background frame (step 5): set `video` (`Auto`, `On`, `Off`) and `background_frame` (`Auto`, `FourThree`, `SixteenNine`, `Screen`) in `ddi.settings.v1`. A song with a movie logs `background video <name>: picture Picture { width, height, bounds }` (the black-bar probe) once it is answered; for a real pillarboxed movie take one from the local packs (`ffmpeg -ss 20 -i <movie> -t 2 -vf cropdetect=limit=24 -f null -` finds the bars) or pad a generated clip (`-vf pad=852:480:106:0`). At 1280×720 a 4:3 frame spans x 160–1120: sample pixels left of 160 for the extension (a dim blur of the frame's edge, never the movie's own bars). Throttle the network (CDP `Network.emulateNetworkConditions`, 1.5 MB/s) to see "loading the video decoder… N %" on the start prompt. `&slow=1` with `Auto` must turn the movie off about 5 s into it (console `background videos turned off for this play: DroppedFrames`, `__DDI_DEBUG.video.open` 0) and the results card must say "video was turned off for this song"; with `On` it plays on; with `Off` no request for `video/ddivideo.*` is made. Autoplay stays all top tier in every case.

## Checks worth repeating after renderer/engine changes

- Receptor order L, D, U, R; arrows coloured by quantization; judgement text and combo centred in the field; life bar at the top; score top-right.
- Autoplay must produce only top-tier judgements (`taps[0]` grows, `taps[5]` stays 0) and `let_go` 0.
- No console errors (`page.on('console')`, `page.on('pageerror')`).
